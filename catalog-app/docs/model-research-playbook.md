# Playbook исследования модели

Этот процесс обязателен для каждой новой landing page. Он позволяет повторять
одну и ту же логику, не смешивать комплектации и показывать происхождение данных.

## 1. Сначала идентифицировать точную версию

Зафиксировать:

- бренд, модель, локальное и китайское название;
- модельный год и точное название комплектации;
- `seriesId`, `specId` и внутренние ID каждого источника;
- тип рынка: официальный РФ, параллельный импорт или автомобиль с пробегом.

Нельзя переносить оснащение соседней комплектации без явной отметки.

## 2. Приоритет источников

1. Официальная страница производителя — силовая установка, ключевые технологии,
   состав комплектации и рекомендованная цена.
2. Китайский автомобильный каталог — полная таблица параметров, фото, категории
   галереи и VR.
3. Второй независимый каталог — проверка размеров, массы, расхода и гарантии.
4. Российский официальный дилер или крупный импортёр — цена под ключ, сроки,
   гарантийные оговорки и локальная терминология.
5. Обзор профильного издания — объяснение уникальных особенностей модели.

Маркетинговые заявления импортёра не считаются техническим первоисточником.

## 3. Правила сверки

- Важные цифры подтверждать минимум двумя источниками.
- При конфликте показывать официальное значение и записывать расхождение.
- Цена в Китае, цена автомобиля в наличии и расчёт «под ключ» — разные поля.
- Расход всегда хранить вместе с циклом измерения: WLTC, CLTC или NEDC.
- Гарантию китайского производителя не представлять как гарантию в России.
- Для неподтверждённого значения использовать `null`, а не догадку.

## 4. Медиа

- Галереи собирать отдельно: экстерьер, интерьер, сиденья и детали.
- Минимум для публикации: 6 фото экстерьера, 6 интерьера, 3 сидений и 3 деталей.
- Каждое изображение хранит `sourceUrl`, категорию и осмысленный русский `alt`.
- Не использовать превью VR как фотографию интерьера.
- До публикации проверить каждое изображение визуально и удалить дубли.
- VR импортировать в локальный viewer: последовательность кадров для экстерьера
  и cubemap-текстуры для интерьера. Это исключает китайские элементы управления,
  внешнюю аналитику и поломки iframe. Для повторного импорта использовать
  `python scripts/import_vr_assets.py --spec <specId> --exterior-id <extId>`.
  Интерьер хранить сценами: место водителя, задний ряд, багажник. Исходный URL
  Autohome сохранять только для атрибуции, не встраивать iframe.

## 5. Уникальный контент страницы

Для каждой комплектации подготовить:

- 4–6 особенностей именно этой версии;
- отличие от младшей и старшей комплектации;
- применимость для России: топливо, климат, мультимедиа, расходники;
- фактический состав цены «под ключ»;
- предупреждения о гарантии, языке интерфейса и сертификации;
- источники и дату последней проверки.

Переведённая таблица характеристик сама по себе не считается уникальной
ценностью страницы.

## 6. Структура данных

Каждая модель должна повторять текущий контракт `src/data/vehicle.ts`:

- основные идентификаторы и цены;
- `highlights`;
- `uniqueFeatures`;
- `gallery` с источником каждого файла;
- `panorama`;
- группы `specifications`;
- `researchSources` с полями `kind`, `name`, `url`, `usedFor`.

При масштабировании этот контракт переносится в базу данных без изменения
компонентов страницы.

## 7. Публикация страницы и её индексация

Страница модели живёт по адресу `/cars/<slug>` и собирается из реестра
`src/data/catalog.ts`. Порядок добавления новой модели:

1. Положить данные модели в `src/data/<slug>.ts` по контракту `Vehicle`.
2. Добавить запись в `catalogModels`: `slug`, `navLabel`, `title`,
   `description`, `summary`, `updated`, `vehicle`.
3. Проверить `/cars/<slug>` локально.

Больше ничего править не нужно: из одного реестра автоматически появляются

- ссылка в промо-строке шапки (`SiteHeader`) на всех страницах сайта;
- ссылка в футере (`SiteFooter`);
- карточка в каталоге на главной (`/#models`) — точка входа для роботов;
- запись в `sitemap.xml` с датой из `updated`;
- микроразметка `Car` + `Offer` + `BreadcrumbList` на странице модели и
  `ItemList` со всеми моделями на главной.

Шапка и футер одинаковы на всех страницах: они подключены один раз в
`src/app/layout.tsx`, поэтому новые страницы получают их автоматически.

Индексацией управляет `NEXT_PUBLIC_SITE_URL`:

- значение с `localhost` — `robots.txt` отдаёт `Disallow: /`, страницы
  помечены `noindex`, прототип не попадёт в поиск;
- реальный домен — открывается индексация, canonical и sitemap начинают
  ссылаться на этот домен. После первого деплоя отдать `sitemap.xml` в
  Яндекс.Вебмастер и Google Search Console.

## 8. Quality gate

Страница готова к публикации, только если:

- точная комплектация подтверждена;
- обязательные характеристики заполнены и сверены;
- медиаквоты выполнены, ссылки работают;
- VR проверен встроенно и отдельной ссылкой;
- расчёт сходится по всем строкам;
- есть российский контекст и минимум три типа источников;
- пройдены lint, build, мобильная и desktop-проверка.
